# HAL CINEMA PC画面のUI方針

月間100万ビューを目指し、初めて訪れた人も作品検索・予約・予約確認を迷わず進められるサイトにする。

参考: [TOHOシネマズ](https://www.tohotheater.jp/)。作品検索、上映状況、購入情報の確認を見つけやすく分ける考え方を参考にした。ロゴや素材、配色をそのまま複製していない。

## 共通の見た目

- 背景は薄いグレー、カードは白、本文は濃いグレー。主要な予約操作と選択中の項目にHALの赤を使う。
- 色は app/globals.css の変数から使い、ページごとに茶色やクリーム色を追加しない。
- 会員ランクの進捗はボルドーと落ち着いた金色。既存のランク画像と予約履歴からの集計を使う。
- 会員ランクはトップページにまとめ、マイページは予約確認・履歴・プロフィール・設定に集中させる。
- 重要な見出しを大きくしすぎず、ラベルと操作ボタンは日本語を先に示す。
- 作品に予約先が用意されていない場合は準備中と表示する。別作品の予約へ誘導しない。

## 操作と動き

- メニューは右側から開く。開閉は160〜240ms程度で、操作を待たせない。
- メニュー内のTab移動、Escapeで閉じる操作、閉じた後のフォーカス復帰に対応する。
- ページ見出し、パネル切替、数量・合計の変化に短い動きを使う。映画の内容を読む邪魔になる常時アニメーションを追加しない。
- 動きを減らす設定では、表示切替を即時にする。
- 広告は初期状態で自動切替しない。広告が1件だけのときは切替操作を表示しない。
- 予約画面では選択内容と次の操作を近くに置く。座席は番号・チェック・予約済みの記号でも区別する。

## 2026-09-08の確認範囲

- PC 1440×1000と1280×900で表示を確認。スマートフォンは今回の確認対象外。
- 検索条件、会員トップ、マイページ、上映日時、座席と券種、フード数量、支払い方法、購入完了を確認。
- 座席と券種の枚数が違う場合、支払い方法が未選択の場合のエラーを確認。
- 支払い確認からフードや座席に戻る際、選択したフード数量が保持されることを確認。
- 予約確定の通信は検証用ブラウザー内でモックし、実際の予約や決済は行っていない。
- 既存の87件のテスト、TypeScript、Lint、本番ビルドが通過。

## 月間100万ビューに向けて

今回の変更はUIと操作性の整備。月間100万ビューの達成や、その規模の負荷に耐えられることを確認したものではない。

次は実際の利用データを使って、初期表示、操作応答、予約途中の離脱、API応答を計測する。作品・上映データの拡充、予約APIの負荷確認を別途進める。
