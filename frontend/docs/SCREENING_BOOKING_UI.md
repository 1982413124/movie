# 上映回選択画面の改修記録

更新日：2026-09-08。対象はPC（1920×1080、1366×768）。

## 変更内容

1. **予約フロー**：鑑賞日 → 上映回 → 座席 → フード → 支払い → 完了。共通ステップの「上映時間」を「上映回」に変更。
2. **削除したUI**：横並びの日付一覧、スクリーン単独の選択、長いあらすじ、ページ内の重複した予約ボタン。
3. **追加したUI**：月間カレンダーのPopover、時刻中心の上映回カード、選択内容を示す下部バー、上映回エリアのLoading・Empty・Error。
4. **カレンダー**：本日、選択日、上映ありの印を表示。上映なし・過去・公開した予約期間の外は選択不可。選択可能日がある月だけ前後に移動できる。選択・外側クリック・Escape・Tabで外へ移動すると閉じる。矢印、Home/End、PageUp/PageDown、Enter/Spaceに対応。
5. **上映回**：開始・終了予定時刻・スクリーン・空席状態を表示。選択中は赤・枠・チェックで示す。完売と販売開始前は一覧に残して無効化。受付終了の回は折りたたんで閲覧できる。
6. **UX**：ポスターを220px（小さいPCでは190px）に抑え、作品情報を1か所にまとめた。開始時刻がカードで最も大きい文字。主要CTAは下部の1つだけで、上映回未選択時は無効。料金は一覧の後に置いた。
7. **動き**：カレンダー160ms、上映回切り替え180ms、Hover 150ms、Pressed 100ms、チェック140ms、下部選択内容180ms。動きを抑える設定では停止する。
8. **主要ファイル**：下記参照。
9. **状態管理**：movieScreeningSelectionに鑑賞日と選択IDを保存。movieReservationDraftにはmovieId、日付、screeningId、screenId、開始・終了時刻をまとめて保存する。日付変更時は上映回の選択を解除。同じ上映回の選び直しでは座席・券種・フードを維持し、別上映ではリセットする。
10. **互換性**：座席・フード・確認・完了の既存データ形式を維持し、終了予定時刻を追加。旧IDの下書きも読み取れる。上映回IDは日付を含む固定IDに変更し、翌日に同じIDを別の上映へ使い回さない。
11. **テスト**：フロント100件、バックエンド19件。日付境界、月末・年末・閏日、日本時間、上映期間との交差、残席分類、固定ID、下書き復元、旧API互換処理、一括取得、通信失敗を検証。
12. **ブラウザで見つけて修正した点**：1366×768ではフードの固定注文欄が882pxあり、支払いボタンが画面下へ隠れていた。短い画面では固定を解除し、長い画面でも注文欄が収まる範囲をスクロールできるよう修正。固定ヘッダーに操作対象が隠れない余白も追加。
13. **静的検証**：lint、TypeScript、全テスト、本番buildを実施。
14. **制約**：下記の「データ・実行環境」を参照。

## PCブラウザの検証

- 1920×1080、1366×768で画面を撮影して目視。横方向のはみ出し・画像欠落なし。
- 1366×768でも最初の上映回がページ上端から約439pxにあり、スクロール前に選べる。
- 日付選択後にカレンダーが閉じ、上映回が変わり、CTAが無効になることを確認。
- カレンダーの前月・翌月、上映のない日、完売・残り19席・販売開始前はブラウザ内の検証用応答で確認。
- APIエラー → 再試行 → 一覧復帰、Empty、上映回だけのSkeletonを確認。
- Escapeで日付ボタンにフォーカスが戻ること、外側クリック、矢印＋Enter、上映カードのSpace選択、Focus Visibleを確認。
- reduced-motion時のPopoverアニメーションがnoneになることを確認。
- リロードとブラウザBackで日付・上映回・座席・券種を復元。
- 支払い → フード → 座席 → フードで、シネマセットA 1点が維持されることを確認。
- 別上映への変更で座席・券種・フードをリセットし、SCREEN 6の70席を正しく表示。
- SCREEN 6 / 2026-09-09 09:30〜11:30 / A-5 / 一般1枚 / フード980円 / 合計2,780円で確認画面まで進行。
- 支払い方法未選択時は送信されず、選択後の予約リクエストは1回。movieId、screeningId、screenId、日付、開始・終了時刻、座席、金額が完了画面まで一致。
- 予約確定の成功応答だけをブラウザ内で置換して完了画面を検証。実際の予約・課金は行っていない。
- 検証用応答はアプリに組み込まず、検証後は通常のAPIに戻した。
- モバイルは今回の実装・検証対象外。

## データ・実行環境

- 現在の上映予定は、従来のseatSelection.mjsにある上映定義（当日から5日後まで、計6日）を再利用している。予約可能期間を14日に拡大する変更はしていない。
- DBには過去の予約に付随した上映回が5件あり、今の上映予定を管理するAPI・公開終了日・販売開始日時の登録はまだない。カレンダーは公開した上映定義を基準にし、映画の開始・終了日が渡された場合はその範囲にも絞る。販売開始日時がある上映回の状態判定には対応済み。
- 新しく表示する残席は予約APIから算出する。旧デモID用の固定予約席を、新しい日付付きIDの空席数には使わない。取得失敗を「全席空席」に置き換えない。
- フロントはWSLの作業ツリー。現在稼働中のDockerバックエンドはWindows側のコードをマウントしている。新しい一括空席APIがない環境では、既存APIを最大4並列で読み取る互換処理が動く。WSL側のバックエンドを反映した環境では1回のDB問い合わせになる。
- この改修はPCの予約UIとデータ引き継ぎの改善。上映予定の本番DBへの移行、実決済連携、夜間上映を含む全上映回での実予約の保証、負荷試験は別途必要。月間100万ビューの実績や負荷耐性を確認したものではない。

## UXレビュー

日付と時刻を選べば次へ進める構成になり、スクリーンを探す操作がなくなった。時刻・空席状態・選択中の表示が読み分けられ、下部のボタンから次に座席を選ぶことが分かる。カレンダーは通常時には場所を取らず、ノートPCでも予約バーと重ならない。短い画面での後続フローの操作不能も修正した。

[TOHOシネマズのインターネットチケット販売](https://www.tohotheater.jp/vit/index.html)を参照し、日付から上映回・座席へ進む導線を取り入れた。配色とカードはHAL CINEMAの共通デザインを使用している。
