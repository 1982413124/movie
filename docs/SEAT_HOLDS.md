# 座席の仮押さえ

最初の座席選択から10分間、同じブラウザの予約手続き用に座席を確保する。座席の追加、リロード、フード選択や支払い画面への遷移では期限を延長しない。選択をすべて解除した後の新しい選択は、新たに10分間確保する。

## DB

`backend/database/seat_holds_migration.sql` を `python manage.py migrate` で適用する。既存の予約・注文・決済データを書き換える移行ではない。

`seat_holds` の列は `showing_id`、`seat_id`、`owner_hash`、`created_at`、`expires_at`。主キーは `(showing_id, seat_id)`。期限は作成時刻から10分以内に制限する。ブラウザにはランダムな所有トークンをHttpOnly・SameSite=StrictのCookieで保持し、DBにはSHA-256ハッシュだけを保存する。会員とゲストの双方に対応し、途中でログインしても引き継ぐ。

仮押さえ取得と予約確定は、対象の `showings` 行をロックして直列化する。両テーブルのトリガーでも同じロックを取り、仮押さえと正式予約の同時成立を防ぐ。従来の `reservation_seats(showing_id, seat_id) WHERE released_at IS NULL` の一意制約はそのまま使用する。アプリのPostgreSQL接続は既定のREAD COMMITTEDを使用する。

空席の判定は必ずDB時刻で `expires_at > clock_timestamp()` を確認する。期限切れの行が残っていても座席は空席扱いになり、次の取得時に期限切れ行を削除する。ブラウザや定期ジョブの起動状態に依存せず、10分後に再取得できる。

予約確定時はサーバー側で所有者、上映開始時刻、全座席の有効期限を再確認する。仮押さえの削除と、注文・予約座席・決済記録・ポイント・通知メール送信待ちの登録は同一トランザクションで処理する。途中で失敗した場合は仮押さえを含めて元に戻す。仮押さえのない旧画面からの確定要求は409で返し、座席の選び直しを案内する。

## API

| メソッド | パス | 用途 |
| --- | --- | --- |
| POST | `/api/reservations/hold-session` | 所有Cookieを準備 |
| PUT | `/api/screenings/{showing_id}/holds/{seat_id}` | 1席を取得。再送で期限は延長しない |
| DELETE | `/api/screenings/{showing_id}/holds/{seat_id}` | 自分が所有する1席だけ解除 |
| GET | `/api/screenings/{showing_id}/holds` | 自分の座席ID、期限、サーバー現在時刻を取得 |
| GET | `/api/screenings/{showing_id}` | 各席の `hold_expires_at` と `held_by_me`、`server_now` を含む |

変更APIは接続元を既存の許可リストで確認する。所有者のハッシュやトークンはレスポンスへ含めない。座席取得の競合は409、存在しない座席は400、通信・DB障害は503として扱う。

## 画面

3000側の `SeatSelectionClient` で、席を押した時点で取得APIを呼ぶ。取得に成功した席だけ選択中にする。自分の残り時間は予約欄、フード選択、支払い確認で表示する。支払い確認では、期限切れや他タブでの選択解除、状態取得エラーがある間は確定ボタンを無効にする。

他の人の仮押さえは黄色で表示する。押したときは選択せず、「この座席は現在、他のユーザーが仮押さえしています。残り6分24秒」のように案内する。座席状況は5秒ごとと画面復帰時に取得する。カウントダウンは受信したサーバー時刻と経過時間から計算し、期限を過ぎた席は空席表示に戻す。キャンセル済みの予約は従来どおり座席を解放する。

## 検証

`backend/tests/test_seat_holds.py` は実PostgreSQLで同時取得、DB直接書き込みの競合、所有者の確認、期限切れ、再送、正式予約への変換、失敗時の復元を確認する。既存の予約、キャンセル、ポイント、クーポン、Resend送信待ち登録のテストも、仮押さえを取得してから実行する。

ブラウザ検証では、独立した2つのブラウザコンテキスト、390pxのモバイル表示、リロード時の期限維持、選択解除、予約完了、期限切れ時の確定ボタン無効化、他の人による再取得を確認する。検証用DBの期限を短縮して表示を確認し、通常のDBにはテスト予約を作らない。
